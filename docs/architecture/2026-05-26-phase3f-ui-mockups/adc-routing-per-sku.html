The G2E is the odd one. Thetis calls it SetRxADC(1) + SetMKIIBPF(1): one ADC, but the modern band-pass filter style. It is a HERMES-class 1-ADC radio wearing a G2 badge, and it behaves like an HL2 for routing purposes, not like its bigger sibling.

Anvelina Pro 3 shares the kOrionMKII row with the 7000DLE / 8000DLE / RedPitaya, so it routes identically to a G2.
Scenario 1  Two slices, 20m + 15m, one antenna
Both inside 11.0-22.0 MHz, so one filter covers them on any radio. Nothing to decide.

Scenario 2  Two slices, 20m + 40m, one antenna
Different ranges (20/15 vs 40/30). This is where the radios diverge, and it is the case that started the conversation.

One ADC means one filter chain. Two ranges cannot both be served, so the chain bypasses and both pans show WIDE. This is correct behaviour, not a defect. The only ways out are closing a slice or moving one to a range the other shares.

Scenario 4  Two slices, 20m + 40m, different antennas
Antenna is the hard constraint: a chain serves one antenna at a time. Here it agrees with the band split rather than fighting it.
RadioRoutingFilteringBadge
G2 AnvelinaA/ANT1 → ADC0   B/ANT2 → ADC120/15 + 40/30none

The G2E case is not a filter problem, it is an antenna problem. One chain cannot be on two antennas, so no filter policy rescues it. This is the §5 conflict-resolution escalation, and it should say so plainly rather than silently picking one antenna and leaving a slice deaf.

The honest summary: on a G2 or Anvelina Pro 3 you have to reach three distinct filter ranges before anything degrades. On a G2E, any cross-range pair bypasses immediately, because it has one ADC. Worth knowing before you bench them side by side and wonder why they differ.
