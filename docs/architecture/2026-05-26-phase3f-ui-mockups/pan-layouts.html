Q7: Pan layout templates (with wideband + overlay model)

AetherSDR has 12 templates + floating windows. Original NereusSDR plan had 5. Wideband adds a new pan type. Let's decide the template set, the per-pan source selector, and floating window support.

What AetherSDR has (source-verified, PanLayoutDialog.cpp + PanadapterStack.cpp)

PanLayoutDialog visible templates (the operator-picker dialog):
  "1" Single  ·  "2v" A/B  ·  "2h" A|B  ·  "12h" A/B|C  ·  "2x2" A|B/C|D

PanadapterStack::rearrangeLayout supports 12 templates (some via API, not all in dialog):
  "1", "2v", "2h", "2h1", "12h", "3v", "2x2", "4v", "3h2", "2x3", "4h3", "2x4"

PanFloatingWindow.h / .cpp: any pan can detach into its own QWidget top-level window. Operator drags it to a second monitor. floatPanadapter(panId) + dockRequested signal.

What's new in NereusSDR 3F

● Per-pan source type: each pan slot is either a DDC pan (one of 5 user DDCs) or a Wideband pan (one of 2 ADCs).
● Source-vs-layout independence: layout templates define geometry, per-pan source picker assigns content.
● AetherSDR doesn't have wideband, so this is genuinely additive — we port AetherSDR's layout shapes 1:1 and add the wideband source option.

Three approaches to the template set

A

Match AetherSDR's full 12-template set

Port all of "1", "2v", "2h", "2h1", "12h", "3v", "2x2", "4v", "3h2", "2x3", "4h3", "2x4". Plus PanFloatingWindow for detach-to-second-monitor.

Pros: 100% AetherSDR muscle memory. Power users with 7-pan / 8-pan setups (matters for big multi-band contest stations) get full capability.
Cons: 12 buttons in the layout dialog is busy. Some templates (4h3, 2x4) overflow normal screen sizes. Most users use ≤4 pans.

B

Trim to 8 ham-relevant templates (recommended)

Keep "1", "2v", "2h", "12h", "2x2", "3v", "4v", "3h2". Drop the 6/7/8-pan templates (operators with those use floating windows on extra monitors instead). All AetherSDR layout shapes that matter for typical operation, none of the overload.

Layout buttons in dialog:
┌─────┬─────┬─────┬─────┐
│  1  │ 2v  │ 2h  │ 12h │
├─────┼─────┼─────┼─────┤
│ 2x2 │ 3v  │ 4v  │ 3h2 │
└─────┴─────┴─────┴─────┘

Pros: Covers ≤4-pan needs. Includes 12h (wide top + 2 below) which is perfect for wideband-on-top + 2 DDC panes. Includes 4v (4 stacked) for HF chasers. Plus floating windows for multi-monitor overflow.
Cons: Contest stations with 5+ panes on one monitor need to use floating windows instead of a one-shot template.

C

Keep original NereusSDR plan's 5 templates

"1", "2v", "2h", "2x2", "12h" only. Drop everything else.

Pros: Smallest UI surface. Matches the 2026-04-09 plan exactly.
Cons: Loses 3v / 4v which are common HF use cases (3 bands monitored vertically on a portrait monitor). Loses 3h2 for the "wide HF + 6m" workflow. Under-shoots AetherSDR's coverage.

Per-pan source picker (new, additive)

Right-click any pan → "Source" submenu
┌────────────────────────────────────────────┐
│  Source        ▶                       │
│  Move to layout slot   ▶   DDC pan (slice A)   │
│  Float pan               DDC pan (slice B)   │
│  Close pan               DDC pan (slice C)   │
│  Equalize sizes         DDC pan (slice D)   │
└─────────────────────────── DDC pan (slice E)   │
                            ─────────────────────┤
                            Wideband ADC0         │
                            Wideband ADC1         │
                            (grays out if SKU has 1 ADC) │
                            ───────────────────────┘

Constraints:
• A single DDC's pan can appear multiple times (different zoom levels of same data)
• Wideband pane choices auto-enable wideband on that ADC (sets packetbuf[23] bit)
• Disabling the last wideband pane for an ADC disables wideband on that ADC
• Slice deleted while its DDC is shown in a pan → pan goes to "DDC pan (no slice)" state (idle FFT) until reassigned

Wideband-on-top workflow with "12h" layout

The "12h" layout becomes the killer wideband layout
Slot A (wide top) — Wideband ADC0 — 0..61.44 MHz
▒▓░░░▒▒█░░░▓░▒░░░░░░░░░░░░░▒░░░░  [band markers and slice flags overlaid]
Slot B — DDC2 (Slice A) — 14.225 ± 96 kHz

Workflow: scan wideband for activity → click a hot spot → DDC pan retunes there → audio reveals signal. Classic SmartSDR/AetherSDR pattern, finally with the wideband visibility OpenHPSDR hardware always had.

Floating windows (multi-monitor)

Port from AetherSDR PanFloatingWindow.{h,cpp} + floatPanadapter() / dockRequested:
  • Right-click any pan → "Float pan"
  • Pan detaches into a top-level QWidget, draggable to any monitor
  • Floating window has a "Dock back" button that returns it to its previous layout slot
  • Persistence: floating window geometry per-pan-id, dock/float state restored on launch
  • Use case: 8-band monitoring station, primary 4 pans on main monitor, extra 4 floated to second/third monitors

Persistence schema (additions)

PanLayoutId = "12h"
Pan0_Source = "ddc:0" # slot A: DDC pan, slice 0 = A
Pan1_Source = "ddc:1" # slot B: DDC pan, slice 1 = B
Pan2_Source = "wideband:adc0" # slot C: wideband, ADC 0
Pan0_Floating = False # docked
Pan2_Floating = True # detached
Pan2_FloatGeometry = "1920,200,800,400" # x,y,w,h on the second monitor
Pan0_CenterMhz = 14.225 # client-side display state
Pan0_BandwidthMhz = 0.192 # client-side display state
Pan0_FftSize = 4096 # client-side display state
Wideband_Adc0_Enabled = True # derived: any pan has wideband:adc0 source

My recommendation: B (8 templates) + per-pan source picker + AetherSDR PanFloatingWindow port. Covers all reasonable single-monitor layouts plus multi-monitor via floating. Wideband-on-top via "12h" is the headline use case.
