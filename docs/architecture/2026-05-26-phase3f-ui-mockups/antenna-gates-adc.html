Antenna selector as the ADC gate (2-ADC boards)

Each ADC is a complete receiver chain: ANT → Alex → ADC → DDCs. On 2-ADC boards you have 2 such chains, so the antenna choice IS what determines which chain a slice lands on.

The mental model

Think of a 2-ADC board as having two parallel receivers, each connected to one antenna at a time:

  Chain 0:  some antenna → Alex0 (HPF + BPF + LPF) → ADC0 → DDCs 2, 4, 6
  Chain 1:  some antenna → Alex1 (HPF + BPF + LPF) → ADC1 → DDCs 3, 5

Each chain is independent. Slices land on whichever chain is connected to the antenna they want. Codec doesn't pick the ADC arbitrarily — it picks based on antenna match.

Antenna preference (per-slice, per-band) → drives ADC routing → determines DDC pool → determines which Alex's BPF applies.

Worked examples on a G2 (2-ADC)

✓ Case 1: Two antennas, clean split
Slice A → 20m → wants ANT1 (HF beam)      → ADC0 (Chain 0 = ANT1)
Slice B → 80m → wants ANT2 (low-band wire) → ADC1 (Chain 1 = ANT2)

Both chains active on distinct antennas. Both Alex BPFs filter their band. No WIDE badge.
✓ Case 2: Two antennas, multi-band on one
Slice A → 20m → ANT1 → ADC0 (Chain 0)
Slice B → 80m → ANT2 → ADC1 (Chain 1)
Slice C → 40m → ANT1 → ADC0 (Chain 0) — joins Chain 0

Chain 0 now has Slices A + C on 20m + 40m → Alex0 BPF goes BYPASS → A & C pans get WIDE
Chain 1 still single-band → Alex1 BPF = 80m → B pan stays filtered, no badge.
⚠ Case 3: Three antennas requested, only 2 ADCs available
Slice A → 20m → ANT1 → ADC0 (Chain 0 = ANT1)
Slice B → 80m → ANT2 → ADC1 (Chain 1 = ANT2)
Slice C → 6m → wants ANT3 → no free chain to switch to ANT3

This is a hard constraint. Operator must choose:
  • Reroute Chain 0 (ANT1) to ANT3 — Slice A loses its antenna (warning before commit)
  • Reroute Chain 1 (ANT2) to ANT3 — Slice B loses its antenna (warning before commit)
  • Settle Slice C on ANT1 or ANT2 (compromise antenna for 6m)
  • Cancel — don't add Slice C until an existing slice is freed

UI: modal dialog when operator picks ANT3 for Slice C, "ADC capacity full" with the 4 options.
✓ Case 4: All slices on one antenna (single-antenna operator)
Slices A, B, C, D, E all on 20m → ANT1 → ADC0 (Chain 0)

All on Chain 0, same band → Alex0 BPF = 20m → all filtered, no WIDE.
Chain 1 (ADC1) sits idle (Alex1 BPF = idle band).

Codec doesn't waste capacity by splitting same-antenna single-band slices across ADCs — keeps Chain 1 free for if the operator adds a different-antenna slice later.

How the codec assignment changes

Codec's slice-to-ADC routing pseudocode (revised)
function assignSliceToChain(newSlice):
  wantedAnt = newSlice.antennaForBand(newSlice.band)
  
  # Find a chain already on this antenna
  for chain in [Chain0, Chain1]:
    if chain.currentAntenna == wantedAnt:
      assignSliceToChain(newSlice, chain)
      return success
  
  # No chain on this antenna — find an idle chain to bring online
  for chain in [Chain0, Chain1]:
    if chain.slices.empty():
      chain.currentAntenna = wantedAnt
      assignSliceToChain(newSlice, chain)
      return success
  
  # Both chains active on other antennas — escalate to operator
  return capacityConflict(wantedAnt, [Chain0, Chain1])

# When operator removes the last slice from a chain:
function chainBecomesIdle(chain):
  chain.currentAntenna = null   # freed for any antenna
  Alex[chain].bpf.state = idle   # last-band memory retained but not engaged

What this changes about earlier decisions

● Per-slice antenna becomes per-band per-slice persistence (matches the per-band pattern we already use). SliceA_Band_20m_Antenna = "ANT1".

● Codec DDC assignment is antenna-driven, not slice-index-driven. Earlier I said "codec assigns by slice index" — this refines that to "codec assigns by antenna match, with ADC capacity as a hard constraint."

● Setup → DDC Routing page becomes mostly informational on 2-ADC boards. The codec handles routing automatically based on antenna preference. The Setup page still exposes per-DDC ADC override for the rare power-user case, but defaults to "auto by antenna" and operators won't touch it.

● The capacity-conflict dialog is a new UI surface. When the operator picks an antenna that would require a 3rd ADC, the dialog explains the constraint and offers explicit choices. No silent failures.

● 1-ADC boards (HL2, Hermes, HermesII) are unaffected — they have only one chain, so antenna is per-band-but-shared-across-slices (matches today's AlexController behavior).

● TX-bound slice's antenna still drives the TX path's antenna selection (existing AlexController.setTxAnt). Independent of RX chain logic.

Each option shows its consequence inline:
  • "currently — would join slice X" = no impact on other slices, joins existing chain
  • "your chain" = no change
  • "would reroute Chain N" = warns that other slices on that chain lose their antenna
  • Each capability-gated per SKU (HL2 only sees ANT1 if that's all hardware exposes)

Per-pan title bar gets one more piece of context

Pan title bar now shows: SLICE X · DDC N · <freq> · <mode> · <bandwidth> · ANT <n> · Chain <0/1>

The "Chain N" tag is the cue that tells the operator which Alex / ADC is in play. Hovering it reveals: "Chain 0: ANT1 → Alex0 (BPF 20m) → ADC0 → DDCs {2, 4, 6}". Click it to open the chain's Filter Policy popup (same one accessible from the WIDE badge).

1-ADC SKUs: chain tag is hidden (only one chain, no choice). Saves clutter.

Locking the model: on 2-ADC boards, antenna is the gate; codec routes slices to whichever ADC is already on (or can be made to be on) the slice's chosen antenna; capacity conflicts (3+ distinct antennas) raise an operator-facing dialog. Push back or refine.
