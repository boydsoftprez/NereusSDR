Diversity port from Thetis — source-first deep dive

Read DiversityForm.cs (2937 lines) + WDSP SetEXTDIV* P/Invokes. Three scope options for how much of the Thetis UI we port.

§1 What diversity actually is (plain English)

Two ADCs both receive the same RF signal (typically: same antenna split into both ADCs, OR two different antennas pointing at the same target frequency). The DSP combines their I/Q outputs with operator-controlled phase shift and amplitude scaling. The combination can:

  • Boost signal-to-noise by ~3 dB when noise on the two ADCs is uncorrelated (basic diversity gain)
  • Null out interference — adjust phase/gain so an unwanted signal cancels between the two paths (powerful for QRM)
  • Steer a phased array — two spatially-separated antennas with phase offset = directional reception (beverage diversity, ground/sky compare)

The 8-memory feature in Thetis stores known-good phase+gain combinations per band — operator dials in a null on a persistent QRM source once, saves to memory, recalls next time it returns.

§2 What Thetis exposes (DiversityForm.cs, 2937 lines)

Thetis DiversityForm — UI inventory
  • chkEnableDiversity — master toggle (green when on / red when off)
  • udR — amplitude scaling factor (0.0 to 10.0, fine adjustment)
  • udAngle — phase angle in radians (-π to +π)
  • udAngle0 — reference angle in degrees (0-359)
  • udFineNull — fine null adjustment (separate slider for precision)
  • chkAuto — auto-adjust mode
  • chkCrossFire — cross-fire toggle (adds π phase shift)
  • chkLockAngle — lock current angle (prevent drift)
  • chkVFOSync — link RX1 + RX2 VFO frequencies together
  • chkNoAttLink — don't link attenuators between RX1/RX2
  • chkAlwaysOnTop — keep dialog above main window
  • btnM1..btnM8 — 8 memory slots (store/recall phase+gain)
  • btnShift180, btnShiftUp45, btnShift90, btnShiftUp10, btnShiftDown10 — quick phase nudge buttons
  • radioButtonMerc1/radioButtonMerc2 — pick reference Mercury ADC
  • udAntSpacing — antenna spacing (meters), for direction-finding
  • udCalib — calibration constant
  • picRadar — animated radar-style visualization of phase + nulls
  • labelDirection — derived direction-of-arrival label
  • Per-band persistence: DiversityPhase160m, DiversityPhase80m, ..., DiversityPhase6m, DiversityPhaseWWV, DiversityPhaseGEN (14 bands × phase + gain = 28 stored values)

§3 The WDSP API (the DSP primitive)

SetEXTDIVRun(channelId, run)      // enable diversity on this WDSP channel
SetEXTDIVNr(channelId, nr)       // number of inputs being combined (2 for standard diversity)
SetEXTDIVOutput(channelId, output)  // 0=combined, 1=primary only, 2=secondary only
SetEXTDIVRotate(channelId, nr, Irotate*, Qrotate*) // complex coefficients per input

The "rotate" coefficients are I = amplitude * cos(phase), Q = amplitude * sin(phase). Operator's phase + gain sliders translate directly to these.

§4 How it fits NereusSDR's slice model

Per-SKU availability: 2-ADC boards only (Angelia, Orion, OrionMkII, Saturn/G2, G2E, Andromeda, AnvelinaPro3, RedPitaya-on-P2). Hardware constraint, gated by BoardCapabilities.hasDiversity.

Which slice is in diversity? Only Slice A (the primary slice). Diversity consumes DDC0 + DDC1 as a synced pair. Slice A's RxChannel reads the combined output.

DDC topology shift (from earlier deep dive):
  • Diversity OFF: Slice A → DDC2 → ADC0 (or ADC1, per Setup routing)
  • Diversity ON: Slice A → DDC0 + DDC1 synced pair, DDC0→ADC0, DDC1→ADC1
  • DDC2 frees up — can host another slice OR sit idle
  • Slices B/C/D/E unaffected (live on DDC3/4/5/6)

UI surface in NereusSDR:
  • "DIV" badge on Slice A's flag + on Slice A's pan SpectrumStatusOverlay when active
  • Tools menu → "Diversity Dialog" (modeless, Ctrl+Shift+D)
  • Right-click Slice A's flag → "Diversity ▶ Off / On" quick toggle
  • Per-band phase + gain stored as SliceA_Band_<band>_DiversityPhase + ...DiversityGain

PS interaction: Diversity and PureSignal both want DDC0+DDC1. PS wins during MOX (per Thetis behavior). Diversity pauses on MOX-on if PS is engaged, resumes on MOX-off. Status indicator on Slice A: "DIV paused (PS active)".

§5 Three port-scope options

A: Minimal — toggle + phase + gain (small, ships fast)
Three controls: Enable checkbox, Phase slider (-180° to +180°), Gain slider (0.0 to 10.0). Per-band persistence for phase + gain. "DIV" badge on Slice A's flag. Tools → Diversity opens a small dialog.

Skipped from Thetis: auto-adjust, cross-fire, lock-angle, VFO sync, attenuator link, 8 memories, quick-nudge buttons, reference Mercury picker, antenna spacing / direction finding, radar visualization.

Pros: ~2 days work. Most operators only ever touch phase + gain anyway.
Cons: Power users lose memories (operators with persistent QRM nulls will miss these). No quick-nudge buttons (have to dial the spinbox).
B: Mid — adds memories + quick-nudge + cross-fire (recommended)
Everything from A, plus:
  • 8 memory slots (M1-M8) per band — store/recall phase+gain combinations
  • Quick-nudge buttons: -10°, -45°, ±90°, +45°, +10°, 180° flip
  • Cross-fire checkbox (adds π phase shift)
  • Auto-adjust button (one-shot find best null)

Skipped from Thetis: radar visualization, antenna spacing / direction finding, reference Mercury picker (we abstract this in codec), VFO sync (different concept in our slice model).

Pros: Covers the canonical SSB DXer workflow (find a null, save it to M3, recall it next time). ~5 days.
Cons: Doesn't have the radar visualization (some operators find it aesthetic / useful for understanding geometry).
C: Full port — radar viz + direction finding + every Thetis control
Everything Thetis has, ported 1:1. ~2 weeks.

Pros: Operators see no regression from Thetis.
Cons: Radar visualization is a custom paint widget (~500 lines). Direction-finding math is niche. Cost vs benefit poor for v1.

§7 What's NOT in scope even at Option B

• Radar visualization — picturesque but doesn't change DSP behavior. Could add as 3F-W polish item.
• Antenna spacing / direction-finding — niche feature, mostly used by beverage-array DXers. Defer.
• Reference Mercury picker — Thetis radio-button choice between Merc1/Merc2 is a 1-Mercury-board concept. NereusSDR codec layer abstracts this (you pick ADC routing in Setup → DDC Routing, not in the Diversity dialog).
• VFO Sync / NoAttLink — VFO sync is a Thetis-RX1/RX2-pair concept that doesn't map to our N-slice model. Operators who want sync set both slices to the same band by hand.
• Auto-attenuator-link — Thetis-specific behavior, ATT plumbing differs in our codec.

My recommendation

Option B (Mid). Covers the SSB DXer canonical workflow (find null, save to memory, recall later). ~5 days. The radar visualization + direction finding are picturesque but don't change the DSP — defer to 3F-W polish or never. The Mercury picker and VFO sync are Thetis-RX1/RX2 concepts that don't map cleanly to our N-slice model anyway, so skipping them is principled, not laziness.

Per-band memories are the genuinely useful Thetis-original feature — operators have specific nulls for specific QRM sources. Worth porting. 8 slots × 14 bands × {phase, gain} = 224 persisted values. Cheap to store, high operator value.

Capability gating: entire Diversity dialog menu item + slice toggle hidden on 1-ADC SKUs (HL2/Hermes/HermesII/Metis) via BoardCapabilities.hasDiversity = (adcCount >= 2).

Push back on the scope — if you want full Thetis parity (radar + direction finding) for the operators who use it, that's Option C. If minimal is fine for v1 and we add memories later, that's A.
