### Atomic activity safety and sender

Create `src/core/safety/RemoteCwSafetyState.h/.cpp`, exported `RemoteCwSafetyState`, holding a single `std::atomic<quint64>`: high 32 bits activity epoch, low bits existing `TxChannel::RfHold` reasons plus private valid/invalidated flags. Do not use its packed flags as protocol bytes. One CAS decides epoch validity and hold clearing, so a physical invalidation cannot lose to check-then-clear. Main allocates nonzero `quint32` epochs, never reuses one in the live server lifetime; refuse exhaustion instead of wrap/reuse. Zero means no remote activity.

```cpp
struct RemoteCwActivity { QByteArray deviceId; quint32 epoch{0}; };
struct RemoteCwSafetySnapshot { quint32 epoch{0}; quint32 holdMask{0}; bool valid{false}; bool invalidated{false}; };
void RemoteCwSafetyState::begin(quint32 epoch);
RemoteCwSafetySnapshot RemoteCwSafetyState::snapshot() const noexcept;
bool RemoteCwSafetyState::setHold(quint32 epoch, TxChannel::RfHold reason) noexcept;
bool RemoteCwSafetyState::clearHold(quint32 epoch, TxChannel::RfHold reason) noexcept;
bool RemoteCwSafetyState::invalidate(quint32 epoch) noexcept;
bool RemoteCwSafetyState::invalidatePhysicalPress(quint32 observedEpoch) noexcept;
void RemoteCwSafetyState::finish(quint32 epoch) noexcept;
bool RemoteCwSafetyState::suppressesCw() const noexcept;
```

`begin` is main-only, called exclusively through the serialized `TransmitCutLine::beginRemoteCw` bridge below, after the prior sender/line is cleared and normal admission succeeds. `invalidate` leaves suppression latched for that epoch until cancellation has cleared remote line intent; `finish` cannot clear a different epoch. Underlying irreversible `transmitCut()` remains independent and always wins. The snapshot is a value, not individually raced loads of fields.

Extend existing RadioConnection with `std::shared_ptr<RemoteCwSafetyState> remoteCwSafetyState() const`, created with the connection; `bool setRemoteCwHold(quint32 expectedEpoch, TxChannel::RfHold reason, bool held)` is any-thread, compares the captured expected epoch and changes its mask in the **same CAS**, then queues `applyRemoteRfHold()` to the connection thread only on success. It never substitutes the currently loaded epoch for a callback's captured epoch. A failed/stale event changes neither protocol nor TX-channel hold. Queued `applyRemoteRfHold()` reads current effective state and sends it; it never applies a captured stale mask. Keep existing non-CW TX-channel hold handling separate. That protected virtual method prompts the existing P1 control-bank/P2 CmdTx+high-priority paths. P1/P2 compose reads the shared safety snapshot and the independent cut at existing late cut seams. The sender and cut line receive this shared state; lifetime setup/teardown follows existing `setTargets` seams.

