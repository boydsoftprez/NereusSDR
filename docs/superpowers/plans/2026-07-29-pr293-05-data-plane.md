# PR 293 Stabilization 05 — Transactional Data Plane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reject an impossible sample-rate narrowing without partially mutating stream/slice/DSP state, and guarantee that audio queued before a slice withdrawal can never reappear after the membership change.

**Architecture:** Sample-rate changes run against a copied `SliceStreamAllocator` plus simulated bindings first. Only a complete placement plan can cross the commit boundary into ReceiverManager, SliceModel, WDSP geometry, and the radio wire. MasterMixer uses an atomic membership generation: the control thread invalidates a withdrawn queue without touching audio-thread ring indices, and the audio thread clears the ring before the first block of a new generation.

**Tech Stack:** C++20, Qt 6, SliceStreamAllocator, WDSP geometry, lock-free audio control atomics, CMake/CTest.

## Task 2: Extract a non-mutating placement planner

- [ ] **Step 1: Define the plan records**

Add private records to `RadioModel`:

```cpp
struct PlannedSlicePlacement {
    int sliceId{-1};
    int previousStream{-1};
    SliceStreamAllocator::Placement placement;
    int resolvedRateHz{0};
};

struct StreamRateChangePlan {
    SliceStreamAllocator allocator;
    QVector<PlannedSlicePlacement> slices;
};
```

Add:

```cpp
std::optional<StreamRateChangePlan>
planStreamSampleRateChange(int streamIndex, int rateHz) const;

void commitStreamSampleRateChange(const StreamRateChangePlan& plan);
```

- [ ] **Step 2: Simulate the complete allocator transition**

`planStreamSampleRateChange` must:

1. reject invalid rate/index without mutation;
2. copy `m_streamAllocator`;
3. apply the requested rate to the target stream, or every active stream for Protocol 1;
4. copy current stable slice IDs, frequencies, stream bindings, and occupancy into local records;
5. run the same `retuneSlice` decision in stable slice-list order;
6. after each simulated placement, update local occupancy, activate/retune/deactivate the candidate allocator exactly as `bindSliceToStream` would;
7. return `std::nullopt` on the first rejection;
8. otherwise return all placements and the final allocator.

Do not call setters, emit signals, update ReceiverManager, touch WDSP, or invoke a connection in this function.

- [ ] **Step 3: Unit-test the planner through the public operation**

Add a widening case to the same test: a successful change returns `true` and produces one coherent signal/assignment batch. Add an invalid-rate case that returns `false` without signals.

## Task 3: Commit the rate change only after successful preflight

- [ ] **Step 1: Change the public result contract**

In `RadioModel.h/.cpp`:

```cpp
bool setStreamSampleRate(int streamIndex, int rateHz);
```

Callers may ignore the result where no UI feedback is needed. `requestSliceSampleRate` should surface the existing placement-rejection status when the result is false.

- [ ] **Step 2: Order Protocol 1 wire mutation after preflight**

For P1, compute the complete plan before `setSampleRateLive(rateHz)`. If planning fails, do not stop/restart the stream or write the rate. If the live wire change fails, return false without committing client state.

- [ ] **Step 3: Apply the successful plan without a second fallible placement pass**

`commitStreamSampleRateChange` must:

- replace `m_streamAllocator` with the planned allocator;
- apply planned stream centres/rates to ReceiverManager;
- update each slice's planned stream, shift, and resolved sample rate;
- republish old/new stream bindings;
- reconcile receiver activation;
- update each affected WDSP channel's shift and geometry;
- emit `streamCentreChanged` after the model is internally coherent;
- call `applyStreamDspGeometry()` once;
- call `requestDdcAssignment()` once.

Do not call `bindSliceToStream()` from the commit step; that would repeat a fallible decision after mutation and reintroduce the defect.

## Task 5: Invalidate queues with an audio-thread generation

- [ ] **Step 1: Add generation state**

In `MasterMixer::SliceState` add:

```cpp
std::atomic<std::uint32_t> streamGeneration{0};
std::uint32_t ringGeneration{0}; // audio thread only
```

The atomic belongs to lifecycle intent. Ring indices and `ringGeneration` remain audio-thread-only.

- [ ] **Step 2: Invalidate on withdrawal without touching ring indices**

In `setSliceStreaming(sliceId, false)`:

- store `streaming=false`;
- store `producing=false`;
- increment `streamGeneration`;
- do not change `rd`, `wr`, `avail`, or the ring vector from the control thread.

On re-admission, store `streaming=true` and arm the existing master up-slew; do not decrement or reuse the prior generation.

- [ ] **Step 3: Reset on the first audio-thread observation**

At the beginning of `accumulate`, after resolving the state:

1. return without queuing when `streaming == false` and the slot is not opportunistic;
2. load `streamGeneration`;
3. when it differs from `ringGeneration`, set `rd=wr=avail=0` and copy the generation into `ringGeneration`;
4. only then ensure/write the new block and enroll the slice.

In both the availability scan and sum loop of `tryDrain`, skip non-opportunistic states whose `streaming` is false. Before using a queue, also ignore it when `ringGeneration != streamGeneration`; the next `accumulate` owns the actual index reset.
